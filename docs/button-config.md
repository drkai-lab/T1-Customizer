# ボタン設定の保存／読み込み

左パネルの「設定を保存」「設定を読み込む」で、ボタン設定一式を
1つの JSON ファイルに書き出し、あとから読み込んで本体へ復元できる。

## 何が保存されるか

書き込みが成功するたびに、アプリは割り当てそのものを
`settings.json` の `buttons` セクションへ記録する（以前は説明文しか
残らなかった）。書き出しファイルには次が入る。

- `buttons` — 全プリセット（レイヤー）×全スロットの割り当て
- `chords` — キーペア押しモードの設定（ペア割り当てと単押し）
- `dial` — ダイヤルの設定（押し込みの動作を含む）
- `assignments` — 各キーの説明文

ファイル形式は次の封筒つき。

```json
{
  "format": "t1-button-config",
  "version": 1,
  "buttons": {
    "1": {
      "1": {"kind": "key", "groups": [[0, 44]], "lone": 0},
      "2": {"kind": "media", "name": "play"},
      "13": {"kind": "mouse", "name": "wheel_up"}
    }
  }
}
```

- `kind: "key"` は本体への書き込み引数そのもの。`groups` は
  （修飾，キーコード）の組の列（最大8組、空はキー無効化）、
  `lone` は修飾キーだけを送る場合の修飾バイト。
- `kind: "media"` / `"mouse"` の `name` はメディア／マウスの
  アクション名。
- 対象スロットは KEY1〜KEY6 とノブの6スロット（13〜18）。

## 読み込みの動作

1. ファイルを検証する。JSON でない、形式タグが違う、対応できない
   新しい `version`、有効なボタン割り当てが1つも無い、といった
   ファイルは理由コードつきで拒否し、何も変更しない。
   検証に落ちた個別の割り当て（未知の `kind`、範囲外のスロット、
   未知のアクション名など）はスキップして件数に数える。
2. 検証を通ったセクションで現在の設定を置き換える
   （ファイルに無いセクションはそのまま残る）。
3. 本体が接続されていれば、記録された割り当てを通常の書き込み
   経路で一括して書き戻し、成功／失敗／スキップの件数を表示する。
   未接続の場合は設定だけを読み込み、「書き込みはまだ」と表示する。

書き戻し時のガードは手動の書き込みと同じ。

- ノブのスロット（13〜18）は、ノブが「キー割り当て」モードの
  ときだけ書き込む（音量モードではスキップ）。
- キーペア押しモードがオンの間、KEY1〜KEY6 へのキー書き込みは
  単押しとして記録され目印が焼かれる。メディア／マウスは
  スキップされる（ペア判定が壊れるため、手動書き込みと同じ扱い）。

## 注意

- 記録は「このアプリで書き込んだ分」だけ。別の手段で本体だけを
  変更しても `buttons` には反映されない。
- 旧バージョンのアプリは `buttons` セクションを無視するので、
  新しい `settings.json` を旧バージョンで開いても壊れない。
