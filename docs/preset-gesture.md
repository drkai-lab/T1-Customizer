# ノブ長押しひねりでのプリセット切り替え / Hold-and-twist preset switching

## 操作

常駐モニタが動いているとき、ダイヤルの押し込みが「音量モード切り替え」
（`dial.press_action = "cycle"`、既定）の状態で:

- **ノブを押したまま右へ回す** → 次のプリセット（1→2→3→1…）
- **ノブを押したまま左へ回す** → 前のプリセット（1→3→2→1…）
- **押して離すだけ（ひねらない）** → 従来どおり音量モード切り替え

1ノッチ（常駐が受け取る回転イベント1回）で1プリセット進む。音量調整と
同じ粒度で、イベントの大きさではなく向きだけを見る。押し込み中に回した
場合、その押し込みは音量モード切り替えとして消費されない（離したときに
モードは変わらない）。押していないときの回転は従来どおり音量変更。

対象は常駐の入力モデルが扱うダイヤルそのもの。押し込みコードは1つ
（学習で保存した `dial.push_code`）、回転コードも1組として扱うため、
OS 側で K1 / K2 を区別しておらず、どちらのノブでも同じ動作になる
（音量操作が元々そうなっているのと同じ）。

「キー割り当て」モード（`dial.press_action = "key"`）ではこの操作は
使えない。ノブは本体内に焼かれたキーとして動作し、常駐は押し込みも
回転も受け取らないため。

## プリセット切り替えの実体

デバイスにはアクティブなレイヤー（プリセット）を切り替えるコマンドが
ある: レポート `[0xA1, layer]`。すべての割り当て書き込みが書き込み先
レイヤーの選択に使っているのと同じもので、常駐はジェスチャのたびに
`switch_layer` としてこれを送る。つまりキーに焼かれた割り当ては実際に
切り替わる。

現在のプリセットは設定の `layer`（GUI のプリセットタブと同じ項目）に
保存され、常駐・GUI・デバイスで1つの値を共有する。常駐の起動時にも、
保存済みプリセットへレイヤー切り替えと LED 書き込みを送ってデバイスと
状態を一致させる。

デバイスへの接続は書き込みの間だけ開いて閉じる（Linux では設定
インターフェースが排他 claim のため、開き続けると GUI が使えなくなる）。
接続や切り替えに失敗した場合はログ（monitor.log）に残し、常駐側の状態
（設定への保存）は維持する。次の起動時・次のジェスチャで再同期を試みる。

## LED について（色は指定できない）

当初の要望は「プリセット1は全部赤、2は青、3は緑」だったが、**本体の
プロトコルに色を指定するコマンドは存在しない**。LED レポートは
`[0xB0, (layer << 4) | 8, mode]` で、ファームウェアの効果プリセット
（mode）しか運ばない。ベンダーアプリをデコンパイルして復元した
プロトコル資料（jgt87/Macropad の PROTOCOL.md、「LED backlight」の節）
にも "There is no colour/brightness/per-LED command." と明記されて
おり、未使用バイトに RGB 値を入れても色は設定できないことが検証済み。
任意の色・キーごとの色にはカスタムファームウェアへの書き換えが要る。

代わりに、プリセットごとに LED の**効果**を変える:

| プリセット | mode | 効果 |
|---|---|---|
| 1 | 1 | 1つ点灯（固定白） |
| 2 | 2 | カラーサイクルのチェイス（全LED） |
| 3 | 3 | 呼吸（パルス、その時点のサイクル色で固定） |

LED の mode はレイヤーごとに本体へ保存される（`write_led` が
`[0xAA, 0xA1]` で保存する）ため、プリセットを切り替えればそのレイヤーの
効果になる。常駐は起動時に現在のプリセット分を書き込み、ジェスチャ時は
そのセッションでまだ書いていないプリセット分だけ書く（フラッシュ
書き込み回数を抑えるため）。LED 書き込みが失敗してもプリセット切り替え
自体は取り消さず、失敗はログに残す。

## 未検証

実機での確認はまだ: ジェスチャでのレイヤー切り替えが本体のキー出力に
反映されること、レイヤーごとの LED 効果が切り替えに追随すること、
Windows / Linux での押し込み・回転イベントの実際の粒度。判定ロジック
（押し＋ひねり→ステップ、タップ→モード切り替え、非押し回転→音量、
両端のラップ）は単体テストで検証済み。
